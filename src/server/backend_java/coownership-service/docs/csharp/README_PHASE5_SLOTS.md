# Фаза 5: переназначение слотов периода

## Назначение
Эта фаза не является отдельным Kafka- или gRPC-контрактом. В коде это доменная операция `PeriodLifecycleService.reassignSlots(...)`, которая меняет владельца отдельных слотов периода.

С точки зрения интеграции C# это внутреннее бизнес-действие backend-сервиса. Если позже появится внешний endpoint, он должен будет лишь передавать те же входные данные в эту доменную операцию.

## Что ожидает сервис на входе
Метод ожидает:

- `periodId` — UUID периода.
- `requesterOwnerId` — UUID владельца листинга, который делает запрос.
- `assignments` — map вида `LocalDate -> UUID`, где ключ это дата слота, а значение это новый ownerId.

Если `assignments` `null` или пустой, метод возвращает `0` и ничего не меняет.

## Бизнес-ограничения
1. Период должен существовать, иначе ошибка `NOT_FOUND`.
2. Запрос может делать только владелец листинга периода.
3. Период не должен быть в статусе `SETTLED`.
4. Для каждой даты в `assignments` должен существовать слот.
5. Можно менять только слоты в статусе `FOR_RENT`.

## Что именно меняется
Для каждого слота из входной карты:

- `ownerId` переписывается на новый UUID.
- `isOverride` становится `true`.

После успешного обновления все слоты сохраняются одним `saveAll(...)`.

## Побочные эффекты
После переназначения сервис пишет в outbox два события:

- `SLOT_OWNERSHIP_CHANGED`
- `SLOT_REASSIGNED`

Оба события содержат одинаковый payload:

```json
{
  "periodId": "8e4d0c8a-9b55-4bb6-94cb-3f22e2a9b7c1",
  "requesterOwnerId": "c9f2f76f-4c0d-4d48-94fe-0d1f8f97b777",
  "assignments": {
    "2026-05-10": "b8d5c8d1-0f7c-4c5d-85df-9b8e2bbf0a11",
    "2026-05-11": "d1d4a2a6-1f5c-4a2b-8a93-d4e7b6edb0aa"
  }
}
```

`assignments` сериализуется как JSON object, где ключи — строки дат `yyyy-MM-dd`.

## Что не меняется
- `templateDaysMask` исходных долей не пересчитывается.
- Статус периода не переводится автоматически в `SETTLED`.
- Операция не создает новый период.

## Что важно C# стороне
1. Это не Kafka и не gRPC-контракт, а внутренняя доменная операция.
2. Если C#-клиент позже получит внешний endpoint для этого сценария, ему нужно будет передавать точные даты слотов.
3. Не передавайте даты, которые не принадлежат периоду.
4. Не ожидайте изменения шаблона следующего месяца.
5. Если вы подписываетесь на Kafka, читайте уже outbox-события `SLOT_OWNERSHIP_CHANGED` и `SLOT_REASSIGNED`.

## Тесты
В репозитории нет отдельного публичного RPC или Kafka-контракта для этой операции. При изменении логики стоит добавлять отдельные unit-тесты на `reassignSlots(...)`, чтобы закрепить правила переназначения и проверки статуса слотов.
